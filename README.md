# aiops-sentinel

Автономный AIOps-агент для малого VPS: наблюдает за продакшен-сервисами,
диагностирует инциденты локальной LLM и выполняет безопасную авточинку
по белому списку. Полностью селфхостед: LLM — Ollama (qwen2.5:3b),
никаких внешних API и платных сервисов.

## Что делает

Каждые 5 минут (cron):

1. **Снимок фактов** — контейнеры Docker, HTTP-проверки эндпоинтов,
   хвосты логов, диск/память/загрузка (`collectors.py`).
2. **Детект** — правила поверх фактов: контейнер упал/пропал, HTTP-фейл,
   медленные ответы, диск/память/LA, всплеск ошибок в логах (`detector.py`).
3. **Диагноз LLM** — инцидент с уликами уходит в локальную модель, ответ —
   строгий JSON: диагноз, вероятная причина, рекомендация и (опционально)
   `action_id` из белого списка (`llm.py`). При недоступности модели —
   честный rule-based фолбэк.
4. **Авточинка с предохранителями** — только заранее описанные действия
   (например `restart:web`), модель не порождает команды; кулдаун,
   суточный лимит, запрет reboot/shutdown на уровне кода (`remediation.py`).
5. **Оповещения** — Telegram-канал (алармы и «восстановлено»), дедупликация
   открытых инцидентов, журнал JSONL (`runner.py`).
6. **Веб-дашборд** — статус сервисов, ресурсы, журнал с диагнозами ИИ;
   вход по паролю, устройство запоминается на год (`web.py`, Flask за nginx).

## Архитектура

```
cron ──▶ runner ──▶ collectors ─▶ detector ─▶ llm (Ollama) ─▶ remediation
              │                                     │              │
              ▼                                     ▼              ▼
        last_snapshot.json   incidents.jsonl   Telegram      docker restart
              ▲                                              (whitelist only)
              └──────────── web dashboard (Flask) ◀──────────────┘
```

## Принципы безопасности

- LLM **советует**, исполняет — код с проверками; никакой генерации команд.
- Белый список действий в конфиге; всё остальное — только аларм человеку.
- Кулдаун 30 мин и лимит 3 действия/сутки на каждое действие.
- `reboot`/`shutdown`/`rm -rf` заблокированы на уровне исполнителя.
- Дедупликация: повторные алармы по открытому инциденту не шлются,
  закрытие подтверждается сообщением «восстановлено».

## Запуск

```bash
cp deploy/config.example.json local/config.json   # отредактировать
python3 -m unittest discover tests                # 10 тестов
python3 -m sentinel.runner local/config.json      # один цикл
# cron: */5 * * * * PYTHONPATH=/path /usr/bin/python3 -m sentinel.runner /path/local/config.json
# дашборд: gunicorn -b 127.0.0.1:8085 sentinel.web:app (за nginx)
```

Зависимости ядра — только стандартная библиотека Python; Flask нужен
лишь дашборду. LLM: [Ollama](https://ollama.com) + любая инструктивная
модель (по умолчанию qwen2.5:3b, ~2 ГБ).

## Продакшен-развёртывание

Работает в бою на VPS (4 vCPU / 16 GB): наблюдает Django-сайт научного
инструментария (веб + БД в Docker), сервис расчёта редукторов и статический
сайт; реальный кейс: обнаружение остановки контейнера → диагноз LLM
(«завершён по SIGTERM») → автоперезапуск за одну итерацию цикла →
подтверждение восстановления в Telegram-канал.
